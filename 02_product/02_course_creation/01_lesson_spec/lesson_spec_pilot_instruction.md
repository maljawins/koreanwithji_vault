# lesson_spec 파일럿 작업지시서

> 첫 파일럿은 **Level 1-1 · How Korean works 한 편**이다. 이 레슨을 `range_set → topic_raw → topic_shaped → lesson_spec → OUTLINE → DRAFT`까지 완주하며 제작 절차를 기록하고 다듬는다. 다른 레슨으로 확장하는 순서는 이 결과를 검토한 뒤 정한다.
> 판단 기준은 [[course_plan]], status 기록법은 [[lesson_spec_tracking]], 용어는 [[glossary]]를 따른다.
> 최종 갱신: 2026-10-13

## 1-1의 현재 위치와 완료 조건

- `1-1`은 `range_set`과 `topic_raw`를 마쳤다. 현재 공식 status는 tracking의 `topic_raw`다. 출발점은 [`1-1_topic_raw.md`](02_topic_raw/Level_1/1_How_Korean_works/1-1_topic_raw.md)와 `range_set_review.xlsx`의 1-1 행이다. 앞단계를 처음부터 다시 하지 않고, 이후 단계에서 원문·구간 불일치를 발견할 때만 해당 단계로 돌아가 고친다.
- 파일럿 완료는 1-1의 `topic_shaped`, `lesson_spec`, Ji가 검수한 OUTLINE, 그 OUTLINE을 바탕으로 작성·검증한 DRAFT가 모두 갖춰지고 tracking에 각 단계의 status와 근거가 남은 상태다. DRAFT까지 만들어 보기 전에는 44개 레슨으로 절차를 일괄 적용하지 않는다.
- 각 단계에서는 **입력 자료 → Agent의 선택과 이유 → Ji가 결정하거나 검수한 내용 → 수정 결과 → 다음 단계로 넘길 기준**을 그 단계의 산출물에 남긴다. 반복해서 적용할 만한 절차 변경은 Ji가 검토한 뒤 이 지시서에 반영한다. status 변경과 예외는 tracking의 `작업이력`에 기록한다. 같은 판단을 여러 문서에 복사하지 않는다.

[[course_plan]] §6의 44개 레슨 범위는 이전 확대안이다. 이번 파일럿 실행에는 적용하지 않는다.

## 앞단계를 새 레슨에 적용할 때

1. V7에서 레슨 번호·제목·주제를 확인하고 바로 앞뒤 레슨의 제목·주제도 읽는다. 제목만 보고 세부 내용을 만들어내지 않는다.
2. 해당 레슨의 Ji Draft가 있으면 먼저 읽는다. Ji가 영상에서 풀려던 핵심 설명과 비유를 확인한다.
3. 트랙별 index와 tracking의 `파일관리`·`외부자료`에서 매핑된 모든 Ref_No·상대경로를 모은다. 실제 파일이 없거나 index와 다르면 중단하고 보고한다.
4. 각 파일이 `duplicate_material_selection.xlsx`의 중복 묶음에 속하는지 확인한다. 중복 여부는 파일명만으로 확정하지 않고 실제 본문을 대조한다.

## `range_set` 작성

1. V7 제목 → brainstorm 참고 → Ji Draft → 모든 매핑 raw의 본문 순서로 읽고, 이번 영상이 **직접 설명할 내용**을 제안한다. 그다음 앞선 내용의 짧은 복습과 다른 레슨에서 자세히 설명할 내용을 나눈다. 판단 근거와 Ji가 결정할 경계는 `range_set_review.xlsx`의 해당 Ref_No `판정 이유`에 적는다.
2. `01_range_set/range_set_review.xlsx`의 `Sheet1`에서 해당 레슨의 모든 Ref_No를 필터링한다. Ji Draft는 파일 전체를 `사용` 한 구간으로 둔다. 다른 자료의 후보 판정은 원문을 직접 확인해 `사용 / 사용 안 함`으로 확정한다. 사용하지 않으면 그 파일에 맞는 구체적인 이유를 남긴다. 후보가 없거나 근거가 약한 파일도 생략하지 않는다.
3. 중복 매핑 파일은 `duplicate_material_selection.xlsx`의 묶음 ID로 연결 레슨을 보고, **같은 원문**의 각 대목을 어느 레슨에서 직접 설명할지 교차 검증한다. Ji Draft 외의 단독 매핑 파일은 자료 전체를 자동 포함하지 않는다. Amira의 동일 수업은 녹화 레슨 → PPT+Script 통합본 → Script 순서로 살피고 하위 자료의 고유 내용을 확인한다.
4. `줄`의 시작·끝과 실제 Markdown 본문을 대조한다. **Ji Draft는 파일 전체를 `사용` 한 구간(1~마지막 줄)으로 기록한다.** 추론한 설명 범위와 어긋나는 대목은 자르지 말고 해당 Ref_No의 `판정 이유`에 Ji 판단이 필요한 이유를 적는다. 다른 자료는 필요한 앞뒤 문단·조건·예외·부정 예문까지 포함한다. 떨어진 대목은 같은 Ref_No의 별도 행으로 둔다.
5. `Sheet1`의 `원문 Ref_No`에 실제 raw 사본을 바로 여는 하이퍼링크를 건다. 트랙별 index의 경로와 실제 파일을 대조해 링크 대상이 해당 Ref_No의 사본인지 확인한다. `자료명`은 이름만 표시한다. 선택 구간이 없으면 `줄`을 비워 두고 `사용 안 함` 이유를 적는다. 주제가 위치명·긴 문장·URL뿐이면 해당 원문을 읽고 짧고 구체적으로 적는다.
6. `판정 이유`에는 **최초 Agent의 파일·구간 채택 이유와 판단 배경**을 남긴다. Ji 피드백을 반영해도 최초 이유와 Ji의 기존 입력을 지우지 않는다. Ji가 결정해야 할 설명 경계, 다른 레슨과의 중복, 자료 부족·출처 충돌은 관련 Ref_No와 원문 대목을 들어 같은 칸에 근거를 적는다. Ji는 `Ji 검토여부`에 직접 `O`를 표시하고 `Ji feedback`에 의견을 쓴다. Agent는 대신 `O`를 표시하지 않는다. 별도 `feedback.md`를 만들거나 갱신하지 않는다. 진행을 막는 문제는 Ji의 방향 결정을 받는다.
7. 매핑된 모든 Ref_No가 `Sheet1`에 있는지, 선택 구간과 원문, `원문 Ref_No` 링크가 일치하는지 확인한다. Ji 의견을 반영할 때는 원문 검증 → 같은 XLSX 수정 순서로 처리한다. `range_set_source_spans*.xlsx`나 레슨별 Markdown 카드에 판정을 다시 기록하지 않는다.

기존 카드와 구간 작업표는 현행 검토 입력처가 아니다. 모든 Ref_No가 `range_set_review.xlsx`에서 최종 판정되고 정확한 구간의 원문 대조, Ji의 설명 경계 검토, 진행을 막는 문제 해결이 끝난 레슨만 tracking을 `range_set`으로 올린다. Ji에게 명확한 개별 구간을 일일이 승인받지 않는다.

## `topic_raw` 작성

1. `range_set_review.xlsx`에서 해당 레슨의 최종 `사용` 행과 `줄`을 확인하고, 실제 raw의 해당 구간만 `02_topic_raw/`의 레슨 파일 `RAW_DIGEST`에 원문 그대로 붙인다.
2. 각 발췌에 Ref_No·상대경로·원문 제목·줄 번호를 붙인다. 요약, 번역, 출처 혼합, Ji식 재서술은 여기서 하지 않는다.
3. 발췌와 실제 원문을 문자 그대로 대조한다. 범위 밖 문장, 제목만 있고 본문이 없는 구간, 필요한 조건·예외 누락이 있으면 `range_set`으로 돌아가 고친다.
4. 모든 사용 구간이 발췌됐고 출처·문자열 대조를 통과한 뒤에만 tracking을 `topic_raw`로 올린다.

## 1-1을 DRAFT까지 실행하며 절차 개발

1. **`topic_shaped`:** 1-1의 `RAW_DIGEST`를 설명 주제별로 묶는다. 출처별 주장·예문·조건·차이를 Ref_No와 원문 줄로 비교하고, 영상에 채택·이월·보류할 요소와 이유를 기록한다. Ji Draft의 설명 흐름과 1-1에 확정된 경계를 기준으로 영상 설명 순서를 만든다. 자세한 형식과 검사는 [[topic_shaped_plan]]을 따른다. 진행을 막는 정확성·경계 문제가 남지 않아야 다음 단계로 간다. Ji의 새 방향 결정이 필요한 내용은 판단을 받은 뒤 반영한다.
2. **`lesson_spec`:** 확정한 설명 순서와 선택 근거를 `GOAL`, `SKELETON`, `TEACHING_POINTS`, `NEW`, `PREREQ`, `BUDGET`, `OUT_OF_SCOPE`, `SOURCES`, `RAW_DIGEST`, `OPEN` 등 필요한 필드에 담는다. 1-1에서 학생에게 설명할 내용과 다음 레슨으로 넘길 내용을 분리하고, 출처·예문 수준을 검증한다. 선택 이유와 미해결 판단을 산출물에 남겨 Ji가 검토할 수 있게 한다. 필수 필드와 근거가 맞고 진행을 막는 문제가 없을 때 다음 단계로 간다.
3. **OUTLINE:** [[lesson_design_method]]의 Skeleton → Flesh 흐름으로 1-1의 영상 뼈대, 설명 순서, 예문·전환 지점을 설계한다. 어떤 `lesson_spec` 근거를 어디에 쓰는지 보이고, Ji의 검수 의견과 반영 결과를 남긴다. **Ji가 OUTLINE을 검수한 뒤** DRAFT를 쓴다.
4. **DRAFT:** 승인된 OUTLINE에 BEAT와 실제 설명을 채워 최종 영상 설계서를 만든다. 학생에게 말하는 톤은 [[01_brand#8. Brand Tone (학생에게 말할 때의 대본 톤)]]을 따르고, 예문은 1-1의 해당 시점까지 가르친 `BUDGET`을 넘지 않게 검증한다. OUTLINE과 달라진 대목은 이유를 기록하고 Ji가 최종 결과물을 검수할 수 있게 한다.

각 단계의 산출물은 해당 작업 폴더의 1-1 레슨 경로에 두고, 파일을 만들 때 raw의 `Level_1/1_How_Korean_works` 폴더명과 맞춘다. 파일명 규칙이 아직 정해지지 않은 단계는 그 단계에 착수할 때 확인해 기록한다. 단계별 산출물의 존재만으로 status를 올리지 않고 [[course_plan]] §7의 완료 조건을 확인한다. 이번 파일럿에는 worksheet와 assignment를 포함하지 않는다.

raw는 읽기 전용이다. `02_ext_sources`·`03_original_PDF`는 Ji가 레슨과 범위를 지정했을 때만 쓰며, 매핑된 Hangul `06_ext_sources` 복사본은 해당 index를 따른다.
