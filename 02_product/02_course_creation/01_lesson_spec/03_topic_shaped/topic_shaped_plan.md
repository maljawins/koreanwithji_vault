# topic_shaped 작업 계획

> 기준일: 2026-10-01. 강의 제작 순서와 단계별 완료 조건의 정본은 [[course_plan]]이다. 이 문서는 그중 `topic_shaped`를 실제 레슨에 적용하는 방법과 산출물 형식을 정한다.

## 결론

`topic_shaped`는 출처별로 쌓인 `RAW_DIGEST`를 **영상에서 설명할 주제별로 다시 묶고**, 설명의 채택·비채택 이유와 가르칠 순서를 결정하는 단계다. 새 원문을 모으거나 대본을 쓰는 단계가 아니다. 한 레슨의 파일 하나에 판단을 모으고, 진행 상태는 기존 [[lesson_spec_tracking.xlsx]]에만 기록한다. 이렇게 해야 [[range_set_source_spans.xlsx]]의 자료 사용 판정, `topic_raw`의 원문, `topic_shaped`의 설명 선택이 서로 다른 역할을 유지한다.

## 현재 상태와 착수 순서

- `lesson_spec_tracking.xlsx`의 196개 레슨은 `topic_raw` 12개, `raw_mapped` 184개다. 실제 `*_topic_raw.md`도 12개이고 `03_topic_shaped` 산출물은 아직 없다. `01_range_set`의 검토 카드 193개는 완료된 레슨 수가 아니다.
- `topic_shaped`의 입력 자격이 있는 범위는 Hangul 1~6과 Numbers 1~5·7이다. 정확성 문제 등은 레슨별로 해결해야 완료할 수 있다. Numbers-6과 아직 `raw_mapped`인 레슨은 앞 단계의 경계·자료 판정을 먼저 끝낸다. 진행 여부는 착수할 때마다 tracking의 현재값으로 다시 확인한다.
- 첫 사례는 **Hangul-1 한 편**으로 한다. [[Hangul-1_range_set_review]]에서 Ji가 설명 경계를 정했고, [[Hangul-1_topic_raw]]에는 ㄴ·ㅁ 발음에 관한 서로 다른 출처의 설명이 함께 있어 이 단계의 핵심인 비교·선택을 검증할 수 있다. Agent가 한 편을 완성해 Ji에게 판단 결과를 보여 주고, 필요한 형식 수정 후 준비된 나머지 레슨으로 확장한다. 긴 Hangul-3은 이 형식이 작동하는지 확인한 다음 처리한다.

## 레슨별 작업 기준

1. **진입 확인:** tracking의 `status`와 `topic_raw 경로`, 레슨의 `*_range_set_review.md`, XLSX의 `파일판정`·`사용구간`, `*_topic_raw.md`를 맞춘다. Ji가 정한 직접 설명·짧은 복습·다른 레슨으로 넘길 경계를 먼저 읽는다. 최근 자료 이동으로 Ref_No·경로·구간이 달라졌다면 해당 `range_set → topic_raw`를 바로잡은 뒤 시작한다. 이미 문자 대조를 마친 원문 전체를 매번 다시 읽지는 않는다.
2. **주제별로 묶기:** `RAW_DIGEST`의 출처 순서를 영상 순서로 복사하지 않는다. 선택된 모든 사용구간을 설명 대상별로 묶고, Ji Draft의 전체 발췌는 내부 소주제까지 나눈다. 같은 주제의 여러 출처와 단독 출처를 모두 검토한다. `사용` 판정은 비교할 근거를 남겼다는 뜻이지, 그 출처의 모든 주장을 영상에 채택했다는 뜻은 아니다.
3. **설명 선택:** 각 주제에서 출처가 주장하는 내용·조건·예외·비유·예문을 비교한다. Ji가 확정한 레슨 경계와 사실 정확성을 먼저 지킨다. 그 안에서 **큰 그림에서 세부로 이어지는 이해 순서, 비유·예문의 명료함, Ji Draft의 고유한 설명**을 기준으로 채택할 요소와 이유를 적는다. 출처 수를 표결처럼 세지 않으며, 같은 Amira 수업의 녹화본·통합본·Script를 독립된 세 근거로 취급하지 않는다.
4. **영상 순서 구성:** 이번 영상의 큰 그림을 먼저 제시하고 각 설명이 그 그림의 어디에 붙는지 정한다. 짧은 복습, 직접 설명, 조건·예외와 예문, 뒤 레슨으로 넘기는 지점을 연결한다. 이 순서는 [[lesson_design_method]]의 Skeleton → Flesh 원칙과 맞아야 한다. 학습자에게 말할 문장 전체나 `lesson_spec`의 필드를 미리 완성할 필요는 없다.
5. **불일치 처리:** 단순한 표현 차이는 선택 이유로 남긴다. 정확성, 레슨 경계, 자료 부족이 결론을 바꾸는 문제는 원문 줄과 Ref_No를 붙여 `OPEN`으로 남긴다. Agent가 원문·기존 근거로 확인할 일과 Ji가 방향을 결정할 일을 분리한다. 예를 들어 [[Hangul-4_range_set_review]]의 `닭이` 발음 충돌, [[Numbers-1_range_set_review]]의 발췌했지만 절대 규칙으로 채택하지 않기로 한 설명, [[Numbers-7_topic_raw]]의 날짜가 박힌 나이 예문은 그대로 사실이나 영상 설명으로 확정하지 않고 검토한다. 필요한 원문이 빠졌다면 `topic_shaped`에 임의로 덧붙이지 않고 `range_set`의 정본부터 수정한다.

| 출처의 관계 | 처리 기준 |
|---|---|
| 같은 설명의 반복 | 가장 명료하고 정확한 요소를 선택하고 나머지는 보조 근거로 표시한다. |
| 서로 보완하는 설명 | 필요한 조건·예외를 합치되 각 요소의 Ref_No와 원문 줄을 따로 남긴다. |
| 원인·사실이 충돌하는 설명 | 매핑된 근거로 정확성을 확인한다. 해결되지 않으면 `OPEN`으로 두고 하나의 사실처럼 합치지 않는다. |
| Ji의 확정 경계와 어긋나는 설명 | 비교 기록은 남기되 영상에는 채택하지 않는다. 경계 자체의 수정이 필요하면 Ji에게 판단을 요청한다. |

## 필요한 파일과 형식

| 파일 | 역할과 생성 시점 | 형식 |
|---|---|---|
| `03_topic_shaped/topic_shaped_plan.md` | 이 문서. 작업 기준의 단일 출처 | 현재 상태, 진입 조건, 비교·선택 순서, 파일 형식, 완료 검사 |
| `03_topic_shaped/03_topic_shaped.md` | 첫 레슨 산출물을 만들 때 필요한 폴더 index | 폴더 역할 한 문장과 이 계획, tracking, 레슨 파일의 경로 규칙을 가리키는 짧은 지도. 판단 내용이나 레슨 목록을 복사하지 않음 |
| `03_topic_shaped/<레벨>/<레슨 폴더>/<레슨 ID>_topic_shaped.md` | 진입 조건을 통과한 레슨마다 한 개 | 아래 형식. 원문 전문을 다시 붙이지 않고 Ref_No·원문 줄로 근거를 가리킴 |
| 기존 `lesson_spec_tracking.xlsx` | 레슨별 공식 진행 상태 | `레슨진행`의 기존 `status`, `작업일자`, `topic_shaped 경로`, `다음 조치`와 `작업이력`을 갱신. 새 시트나 별도 판정 XLSX는 만들지 않음 |

레슨별 파일의 기본 형식은 다음과 같다. 표와 주제 절의 행 수는 레슨 내용에 따라 늘린다.

```markdown
---
lesson_id: "<레슨 ID>"
stage: "topic_shaped"
---

# <레슨 ID> topic_shaped

## 입력과 확정 경계
- V7 레슨 제목: ...
- 경계 결정: [[<레슨 ID>_range_set_review]]
- 원문 발췌: [[<레슨 ID>_topic_raw]]

## 주제별 설명 선택
### 1. <설명 대상>
- 출처별 주장: <Ref_No · 원문 줄 · 내용/차이>
- 영상에 채택할 요소와 쓰임: ...
- 채택 이유: <정확성, 경계, 이해 순서, 비유·예문, Ji 설명 중 해당 근거>
- 비채택·이월·보류한 요소와 이유: ...

## 영상 설명 순서
| 순서 | 큰 그림에서 이어지는 설명 | 연결 이유 | 근거 Ref_No·원문 줄 |
|---|---|---|---|
| 1 | ... | ... | ... |

## 사용구간 처리 확인
| 구간 ID | 주제 절 | 처리 | 이유 |
|---|---|---|---|
| <레슨 ID + Ref_No + 구간 순번> | 1 | 채택 / 보조 / 비채택 / 이월 / 보류 | ... |

## OPEN과 다음 단계 전달
- Ji가 정할 내용: <없음 또는 근거와 선택지>
- Agent가 확인할 사항: <없음 또는 확인할 원문·사실>
- lesson_spec에 넘길 핵심: <설명 순서, 예문 후보, 선수 내용·BUDGET 확인점>
```

`사용구간 처리 확인`에는 XLSX의 `사용구간`마다 적어도 한 행을 둔다. 하나의 구간에 서로 다른 소주제가 있으면 같은 구간 ID를 여러 행에 쓰고 해당 내부 줄을 밝혀 빠진 부분이 없게 한다. `비채택`은 해당 설명을 비교한 뒤 영상에서 쓰지 않는다는 뜻이며, XLSX의 자료 `사용` 판정을 뒤집지 않는다. `보류`는 해결 전까지 완료를 막는다. Ji Draft만 있는 레슨은 억지로 출처 간 비교를 만들지 않고, 그 안의 설명 대상과 Ji의 의도·영상 순서를 검토한다.

현재 비어 있는 `03_topic_shaped`의 `Level 1`·`Level 2` 폴더명은 raw의 `Level_1`·`Level_2`와 다르다. [[01_lesson_spec]]의 폴더명 일치 규칙에 따라 해당 레슨의 파일을 만들기 전에 폴더명을 raw에 맞추는 별도 정리가 필요하다. 이번 계획 작성이나 Hangul-1 사례에는 영향을 주지 않는다.

## 완료 검사와 다음 단계

- 모든 `사용구간`이 처리 확인표에 나타나고, 영상에 채택한 설명·비유·예문에 Ref_No와 원문 줄이 붙어 있다. 단독 출처, Ji Draft 전체 발췌, 여러 출처의 차이도 빠지지 않는다.
- 영상 설명 순서가 Ji의 확정 경계를 넘지 않고, 선행 설명 없이 예외부터 등장하지 않는다. 날짜에 따라 달라지는 예문과 정확성 우려를 다시 확인한다.
- 진행을 막는 `OPEN`이 없고 위 검사를 통과한 뒤에만 tracking을 `topic_shaped`로 올리고 파일 경로와 작업 근거를 `작업이력`에 남긴다. Ji의 새 방향 결정이 필요한 경우에는 그 판단을 받은 뒤 반영한다.
- 다음 `lesson_spec`에서는 이 파일의 선택·순서를 `GOAL`, `SKELETON`, `TEACHING_POINTS`, `NEW`, `PREREQ`, `BUDGET`, `OUT_OF_SCOPE`, `SOURCES`, `OPEN` 등 필요한 필드로 옮기고 검증한다. `OUTLINE`과 `DRAFT`의 대본 작업은 그다음 단계다.

## 판단 근거

- [[course_plan]] §3~5·§7: 관련 원문은 `range_set`과 `topic_raw`에 모두 남기고, `topic_shaped`에서 설명을 비교·채택하며 영상 범위와 순서를 구성한다.
- [[lesson_spec_pilot_instruction]]과 [[lesson_spec_tracking]]: 완료된 발췌만 다음 단계로 넘기고 레슨 단위로 status를 기록한다.
- [[lesson_design_method]]: 전체 구조를 먼저 보여 주고 세부 설명을 붙이는 순서가 영상 설계의 기준이다.
