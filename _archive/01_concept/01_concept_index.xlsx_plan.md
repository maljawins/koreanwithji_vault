# `01_concept_index.xlsx` 칼럼·정렬 설계

> 최종 갱신: 2026-09-18. 레슨 단위 조사·원문 명칭 근거·확인 요청 관리 반영.

## 1. 기본 구조

**개념의 정의는 [[glossary#3. 작업]]을 따른다.** 따로 설명할 수 있다는 이유만으로 개념을 만들지 않는다. 문법 표현도 개념이 될 수 있으며, 판단이 애매하면 [[concept_review_questions]]에 남긴다. 모든 자모·일반 어휘·설명 제목·주장·연습 활동을 자동 등록하지 않는다.

**조사·등록 단위는 레슨 하나에 매핑된 자료 전체다.** 파일별로 후보와 근거를 모으고, 전체 허용 구간을 검토한 뒤 같은 개념·다른 명칭·설명 충돌을 비교하여 등재한다. 개념 인덱스는 레슨 전체 내용 목록이 아니며, 개념에서 제외한 설명·연습이 레슨에서도 제외된다는 뜻은 아니다.

`01_concept_index.xlsx`의 구조와 실제 조사·범위 검수는 이 문서를 따른다. 현재 조사 결과와 개정 이력은 [[concept_work_fix_plan]]에서 확인한다. 옛 목록 `concepts_old_vault`는 문서 형태만 참고하며 이름·출처·레슨 연결을 가져오지 않는다.

- 조사 대상과 파일 수 확인사항: [[course_plan#9. 파일럿과 확장]].
- 시트: `개념사전`, `자료별개념`, `레슨별범위`.
- 연결 방식: **개념 번호로 세 시트를 연결하고, Ref_No로 원본 파일을 찾는다.**
- 파일별 검토 상태와 제작 진행 단계는 기존 `lesson_spec_tracking.xlsx`에서 관리한다.

## 2. 시트별 칼럼

아래 표 순서가 실제 왼쪽부터의 칼럼 순서다.

### `개념사전`

**한 행 = 개념 하나의 별칭 하나.** 레슨과 관계없이 같은 개념에는 같은 번호를 쓴다. 별칭이 여러 개면 같은 `concept_id`·`표준명`으로 행을 추가하고, 별칭이 없으면 별칭 칸을 비운 한 행을 둔다.

| 칼럼 | 기록할 내용 |
|---|---|
| `concept_id` | `C000001` 형식의 고정 개념 번호 |
| `표준명` | 실제 조회한 원본에서 사용한 영어 개념명. 영어 명칭이 없으면 한국어 표기를 유지하며 임의 번역·로마자화하지 않음 |
| `별칭` | 조회한 원본에 등장하며 같은 개념을 뜻하는 다른 이름. 확인된 이름이 없으면 빈칸. 별칭 하나당 별도 행 |
| `짧은 정의` | 이 개념이 무엇인지 설명하는 1~2문장 |
| `개념 경계` | 비슷한 개념과 구분하는 기준과 포함되는 세부 조건 |
| `확인사항` | [[concept_review_questions]]의 질문 번호. 질문 본문과 답변은 중복 기록하지 않음 |
| `표준명 근거` | 표준명이 실제 쓰인 구간의 evidence_id. 같은 concept_id의 대표 행에 기록 |
| `별칭 근거` | 해당 행 별칭이 실제 쓰인 구간의 evidence_id. 별칭이 없으면 빈칸 |

**표준명과 별칭은 실제 원문에 등장하는 명칭만 쓴다.** 영어 표준명을 우선하되 영어 명칭이 없으면 `ㄹ`처럼 한국어를 유지하며 `rieul`처럼 만들지 않는다. 단수·복수나 번역으로 원문에 없는 이름을 생성하지 않는다. 같은 뜻의 이름 후보 중 선택이 불명확하면 질문으로 남긴다. 기존 한국어 표준명도 원문 등장과 의미 일치가 확인된 경우에만 별칭으로 남긴다. 관련 개념·상위 개념·하위 개념은 별칭이 아니다.

표준명·별칭의 각 근거는 같은 concept_id에 연결되어야 하고, 해당 근거의 줄 범위 안에서 명칭이 실제로 확인되어야 한다. 원문 표현과 짧은 시작 인용을 함께 대조한다. 정의·설명은 근거에 맞춰 한국어로 요약할 수 있지만 그 요약을 개념명으로 승격하지 않는다. 표시용 표준명은 연결된 시트에서 함께 갱신한다.

등록 자격을 통과한 후보끼리 의미·용법을 비교한다. 같은 형태라도 다른 개념이면 구분하되, 단순히 예문이나 레슨이 다르다는 이유로 나누지 않는다. 애매한 후보는 임시 개념 번호를 부여해 확정 등재하지 않고 확인 파일에 남긴다.

별칭 배치 예시이며 실제 조사 데이터는 아니다. 아래 이름도 각 원본 근거를 확인한 뒤에만 실제 등록할 수 있다.

| concept_id | 표준명 | 별칭 |
|---|---|---|
| C000001 | Romanization | 로마자 표기 |
| C000002 | Consonant | 자음 |
| C000002 | Consonant | Consonants |

`짧은 정의`·`개념 경계`·`확인사항`·`표준명 근거`는 같은 concept_id의 대표 행 하나에만 기록한다. 추가 별칭 행에서는 이 칸들을 비우고, 프로그램은 행 번호가 아닌 concept_id로 대표 행의 값을 찾는다. 별칭 수가 늘어도 개념 수는 늘지 않는다.

`종류` 칼럼은 삭제한다. OUTLINE·DRAFT에서 이 분류를 사용하는 규칙과 서로 겹치지 않는 분류 기준이 없으므로 유지하지 않는다. 개념의 구분은 `짧은 정의`와 `개념 경계`로 판단한다.

### `자료별개념`

**한 행 = 한 파일의 한 구간에서 주된 주제로 직접 설명한 개념 하나.**

Ji 레슨과 raw 파일의 매핑 기준에 맞춰, 원본 자료가 주된 주제로 가르치는 개념만 기록한다. 복습·단순 언급·예문 속 등장만으로는 개념 행을 만들지 않는다. 직접 설명한 개념의 예문·조건·예외는 그 개념의 근거로 함께 확인한다. 같은 개념을 서로 다른 구간에서 직접 설명하면 근거를 구분해 기록할 수 있다.

| 칼럼 | 기록할 내용 |
|---|---|
| `evidence_id` | `E000001` 형식의 고정 근거 번호. 레슨별범위의 판단을 이 설명 구간에 연결 |
| `Ref_No` | 기존 index의 파일 번호 |
| `Ji 레벨` | Ref_No에 연결된 레벨 |
| `Ji 레슨` | Ref_No에 연결된 레슨 번호 |
| `Raw 종류` | 기존 index의 트랙 |
| `자료형태` | Script·통합본·녹화본 등의 기존 분류 |
| `concept_id` | 개념사전과 연결하는 번호 |
| `표준명` | 개념사전에서 가져오는 표시용 이름 |
| `원문 표현` | 자료가 실제로 사용한 개념 이름·표현 |
| `다룬 내용` | 해당 구간이 설명하는 의미·조건·예외의 짧은 요약 |
| `시작 줄` | 현재 Markdown 파일 첫 줄을 1로 센 해당 설명 구간의 시작 줄 |
| `끝 줄` | 해당 설명 구간의 끝 줄 |
| `원문 근거` | 시작 줄의 원문 첫 몇 단어를 그대로 인용하고 `...`로 줄인 위치 확인용 문구 |
| `확인사항` | 출처 간 설명 충돌·해석 불명확에 해당하는 확인 파일 질문 번호 |

`evidence_id`는 **범위 판단에 붙이는 근거 번호표**다. `Ref_No`는 파일, `concept_id`는 개념, `evidence_id`는 그 파일의 특정 구간에서 해당 개념을 설명한 근거를 가리킨다. `레슨별범위`의 `근거 번호`로 연결하므로 정렬·행 삽입 후에도 같은 설명 구간을 찾을 수 있다. 한 근거를 여러 레슨의 범위 판단에 연결할 수 있으며 번호를 다시 매기거나 재사용하지 않는다.

위치는 모든 자료에서 **Markdown 줄 번호 + 원문 첫 몇 단어와 `...`**로 통일한다. `섹션·구간` 칼럼은 삭제하고 제목·슬라이드·시간 표기를 별도 위치 기준으로 쓰지 않는다. 줄 번호는 frontmatter와 빈 줄을 포함해 센다. 인용은 원문 그대로이며 `...`는 생략 표시다. 시작 문구만으로 구별하기 어려우면 인용 단어를 늘린다. 이 짧은 인용은 위치 확인용이며, 판단은 시작 줄부터 끝 줄까지의 실제 설명을 읽어 확인한다.

`등장 방식` 칼럼도 삭제한다. 모든 행이 직접 설명 기준을 통과해야 하므로 같은 값을 반복 저장할 필요가 없다.

레벨·레슨·트랙·자료형태·표준명은 연결된 정본에서 가져오는 값이다. 이 시트에서 독립적으로 수정하지 않는다. 파일 경로는 Ref_No로 기존 index에서 찾는다.

### `레슨별범위`

**한 행 = 레슨 하나에서 개념 하나를 어떻게 다룰지에 대한 결정.**

| 칼럼 | 기록할 내용 |
|---|---|
| `Ji 레벨` | V7 기준 레벨 |
| `Ji 레슨` | V7 기준 레슨 번호 |
| `Ji 레슨 Title` | V7 기준 제목 |
| `concept_id` | 검수할 개념 번호 |
| `표준명` | 개념사전에서 가져오는 이름 |
| `범위 판단` | 포함 / 제외 / 보류 |
| `다룰 범위` | 이번 레슨에서 설명할 의미·조건·깊이 |
| `다루지 않을 범위` | 같은 개념 안에서 이번에 제외할 부분 |
| `판단 이유` | 포함·제외·보류를 제안한 이유 |
| `근거 번호` | 연결되는 evidence_id. 여러 개면 셀 안 줄바꿈 |
| `설계 근거` | Ji Draft·개념 조사 결과·앞뒤 레슨을 대조한 근거. V7의 `Ji 레슨 주제`는 참고 내용으로 구분해 기록 |
| `이관 레벨` | 다른 레슨으로 미루는 경우 실제 대상 레벨 |
| `이관 레슨` | 다른 레슨으로 미루는 경우 실제 대상 레슨 번호 |
| `Ji 검수` | 미검수 / 수정 요청 / 확정 |
| `검수 메모` | Ji의 수정 지시 또는 확정 조건 |
| `검수일` | Ji가 검수한 날짜 |

`범위 판단`은 Agent의 제안으로 시작한다. **처음 제안할 때 V7 커리큘럼맵의 `Ji 레슨 주제` 칼럼은 Ji의 의도를 이해하는 참고자료로만 사용한다.** 그 칼럼에 있다는 이유만으로 포함하거나, 없다는 이유만으로 제외하지 않는다. 실제 직접 설명 근거, Ji Draft와 앞뒤 레슨을 대조해 범위를 제안하고 `판단 이유`를 남긴다.

**`포함`이면서 `Ji 검수 = 확정`인 범위만 발췌에 사용할 수 있다.** 레슨의 모든 범위 판단이 Ji 검수로 확정되고 미검수·수정 요청·보류가 남지 않아야 범위 확정으로 본다. 이후 진행 상태는 [[course_plan#5. 작업 검토표]]의 `range_set` 기준을 따른다.

`NEW`·`PREREQ`·`THROUGH_LINE`과 실제 강의 순서는 이후 lesson_spec 단계에서 결정한다. 자료의 ‘직접 설명’을 자동으로 `NEW`로 바꾸지 않는다.

## 3. 데이터 정렬·표시 규칙

| 시트 | 기본 정렬 |
|---|---|
| 개념사전 | 표준명 → concept_id → 별칭 |
| 자료별개념 | V7 레슨 순서 → 트랙 순서 → Ref_No의 파일 순번 → 시작 줄 → concept_id |
| 레슨별범위 | V7 레슨 순서 → concept_id |

- 파일럿 레벨 순서는 **Hangul → Numbers → Level 1 → Level 2**. 레슨 번호와 파일 순번은 숫자로 정렬한다.
- 트랙 순서는 **Ji Draft → YouTube → Amira → HTSK → web**.
- 번호는 최초 부여 후 고정한다. 행을 정렬하거나 삽입해도 다시 매기지 않는다. 제거된 번호는 재사용하지 않으며, 개정 이력에 남은 최대 번호 다음부터 부여한다.
- 각 시트는 머리글 1행과 연속된 데이터 표 하나로 구성한다. 셀 병합·중간 빈 행·레슨별 소제목 행은 넣지 않는다.
- 머리글과 식별 칼럼을 고정하고 모든 칼럼에 필터를 적용한다.
- 범위 판단·Ji 검수 값은 선택 목록으로 제한한다. 색은 보조 표시로만 쓴다.
- 프로그램이 읽을 때는 열 위치가 아닌 **헤더 이름**으로 찾는다.
- 기본 정렬은 조회 순서다. 실제 가르칠 순서를 뜻하지 않는다.

## 4. 조사와 이후 작업의 연결

1. 기존 관리표의 `파일관리`와 `외부자료`에서 레슨 하나의 전체 Ref_No·실제 파일 목록을 확정한다. 옛 목록의 매핑은 사용하지 않는다.
2. 각 파일의 허용 구간을 읽고 용어 후보·실제 명칭·설명 근거를 수집한다. 단순 언급·복습·예문만으로 등록하지 않는다.
3. 레슨 전체 자료의 검토가 끝나면 같은 개념·명칭 차이·범위 차이·설명 충돌을 대조한다. 같은 개념의 근거는 파일별로 유지한다.
4. 확실한 개념과 원문 근거가 있는 이름을 `개념사전`·`자료별개념`에 등록한다. 조사된 용어가 현재 레슨 제목과 다르다는 이유만으로 버리지 않는다.
5. 애매한 항목은 [[concept_review_questions]]에 모은다. **Ji의 2026-09-18 지시에 따라 질문 때문에 레슨 전체 작업을 멈추지 않는다.** 확실한 항목과 독립적인 조사는 계속하며, 해당 항목의 확정·통합·별칭 등록만 보류한다. 답변을 추측해 채우지 않는다.
6. 미검토 자료 또는 미해결 질문이 있으면 레슨 조사를 완료 처리하지 않는다. 실제 검토 여부와 확인 대기 여부를 tracking에 구분해 기록한다.
7. 조사 결과로 `레슨별범위`를 제안하고 Ji가 검수한다. 범위 확정 조건을 충족해야 `range_set` 이후 발췌로 진행한다.

### 확인 요청 관리

- 확인 파일은 [[concept_review_questions]] 하나를 사용한다. 레슨별 질문에 고정 질문 번호, 후보 표현, Ref_No·실제 경로·줄 범위·원문, 애매한 점, 확인 질문 하나, 제안과 이유, Ji 답변, 상태를 기록한다.
- 상태는 `확인 대기 / 답변 완료 / 반영 완료`다. 답변을 받은 뒤 관련 개념·근거·범위에 반영하고 결과를 기록해야 반영 완료로 바꾼다.
- 답변 완료 항목도 삭제하거나 번호를 재사용하지 않는다. 인덱스에는 질문 번호만 연결한다.
- 읽었으나 개념이 없는 파일과 미검토 파일을 구분한다. 질문 때문에 미등록인 후보를 개념 없음으로 처리하지 않는다.

운영 경계는 다음과 같다.

- 트랙별로 읽을 수 있는 구간은 [[course_plan#6. 개념 조사와 범위 검수]]를 따른다. 그 안에서도 위의 직접 설명 기준을 적용한다.
- 개념이 없는 파일이나 조사 제외 파일에 가짜 개념 행을 만들지 않는다. 기존 tracking에 검토 결과와 사유를 남긴다.
- 같은 원본의 다른 레슨 사본은 각 Ref_No를 유지한다. 같은 개념이면 concept_id는 공유한다.
- 같은 Amira 세션의 여러 파일을 독립 출처 여러 개로 세지 않는다. 근거 행 수는 증거의 강도를 뜻하지 않는다.
- 개념 이름·정의·범위를 바꿔 승인 내용에 영향을 주면 해당 범위를 다시 검수한다.

## 5. 검증·완료 기준

- 레슨별 `파일관리`·`외부자료` 전체 목록과 실제 경로를 대조한다. 모든 허용 구간을 검토했는지, 미검토·개념 없음·확인 대기를 구분하는지 확인한다.
- 모든 표준명·별칭의 근거 번호가 같은 concept_id의 실제 원문 구간으로 연결되고, 이름이 그 구간에 등장한다. 별칭은 관련성뿐 아니라 의미의 동일성을 확인한다.
- 미해결 질문이 있는 레슨을 조사 완료나 범위 확정으로 표시하지 않는다.
- concept_id 하나가 개념 하나만 가리키며, 별칭 행에서 반복된 같은 번호를 중복 개념으로 세지 않는다. `(concept_id, 별칭)` 조합은 고유하고, 개념별 대표 행 하나에만 정의·경계·확인사항이 있다.
- 모든 evidence_id가 고유하며, 연결된 concept_id와 근거 번호의 대상이 실제로 존재한다. 개념사전에서 표준명·정의를 가져올 때 별칭 행 수만큼 근거·범위 행이 늘어나지 않는다.
- 모든 Ref_No가 기존 index·실제 파일과 일치한다.
- 줄 번호가 실제 설명 구간을 가리키고, 생략 표시 `...`를 제외한 인용이 시작 줄의 원문과 일치한다.
- 자료별개념의 모든 행이 주된 주제로 직접 설명한 개념이며, 복습·단순 언급·예문 등장만을 근거로 만든 행은 없다.
- 레슨 하나에서 개념 하나의 범위 결정이 중복 행으로 갈라지지 않는다.
- 정렬 후에도 근거·판단·Ji 검수 내용의 연결이 유지된다.
- 미검수·수정 요청·보류가 남은 레슨은 `range_set`이나 `topic_raw`로 넘어가지 않는다.

기존 workbook을 개정할 때는 이 설계에 맞춰 시트 구조와 입력 제한을 정비한다. 실제 개념과 검수 결과는 조사·검수 과정에서 입력하며 미리 채우지 않는다.
