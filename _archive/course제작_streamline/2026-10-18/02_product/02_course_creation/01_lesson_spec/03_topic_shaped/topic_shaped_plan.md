# topic_shaped 작업 계획

> 기준일: 2026-10-14. 강의 제작 순서의 정본은 [[course_plan]]이다. 이 문서는 `topic_shaped`의 목적, 작업 방법과 산출물 형식을 정한다.

## 결론

`topic_shaped`는 `topic_raw`의 출처별 발췌를 **설명 주제별로 모아**, 각 출처가 무엇을 어떻게 가르치는지 Ji가 한눈에 비교할 수 있게 하는 단계다. Ji는 이 정리를 직접 읽고 강의 구조와 설명 방식을 구상한다. Agent는 여러 설명 중 하나를 임의로 고르거나 조합하지 않고, 채택·비채택 이유도 기록하지 않는다. 자료와 사용 구간의 판정은 [[range_set_review.xlsx]], 원문은 `topic_raw`, 주제별 정리는 `topic_shaped`에 둔다. 새 원문 수집과 대본 작성은 이 단계에서 하지 않는다.

## 착수 조건과 첫 사례

- `topic_raw`를 완료한 레슨이 입력 대상이다. 진행된 레슨 수와 현재 status는 이 문서에 옮겨 적지 않고 착수할 때 [[lesson_spec_tracking.xlsx]]에서 확인한다.
- 첫 사례는 **Level 1-1 · How Korean works**다. [[1-1_topic_raw]]의 여러 출처를 주제별로 정리해 Ji가 읽고 형식을 검토한다. 다른 레슨으로의 확대는 첫 사례를 본 뒤 정한다.

## 레슨별 작업 기준

1. **진입 확인:** tracking의 `topic_raw` 완료 여부와 파일 경로, `range_set_review.xlsx`의 해당 레슨 Ref_No·사용 구간·Ji feedback, `*_topic_raw.md`를 맞춘다. Ji가 정한 직접 설명·짧은 복습·다른 레슨으로 넘길 경계를 먼저 읽는다. Ref_No·경로·발췌가 맞지 않으면 앞 단계를 바로잡은 뒤 시작한다.
2. **주제별로 정리:** `RAW_DIGEST`의 출처 순서를 그대로 따르지 않고 설명 대상을 기준으로 묶는다. 예를 들어 1-1의 word order는 `Ji-1-1-1`, `YT-1-1-1`, `YT-1-1-3`의 해당 설명을 한 주제 아래 나란히 둔다. Ji Draft의 파일 전체 발췌는 소주제로 나누고, 한 자료에만 있는 설명도 빠뜨리지 않는다. 각 내용의 Ref_No·원문 줄을 클릭 가능한 링크로 표시해 실제 raw 사본의 해당 범위 **시작 줄**로 이동하게 한다. 한 출처에 범위가 여러 개면 범위마다 따로 링크를 건다. 주제 표뿐 아니라 강의 구조 메모, 사용구간 확인표, `OPEN`의 출처 표기에도 적용한다.
3. **설명 방식 드러내기:** 출처별 핵심 주장, 설명 순서, 비유·시각 자료, 예문, 조건·예외를 짧게 정리하고 차이가 있으면 나란히 보여 준다. 서로 다른 설명을 한 문장으로 합치거나 대표 설명 하나만 남기지 않는다. Ji가 직접 조합하거나 새 설명을 구상할 수 있도록 원문별 관점을 보존한다.
4. **영상 구조 구상용 배열:** 주제를 Skeleton → Flesh의 큰 그림에서 세부로 읽을 수 있게 배열한다. [[lesson_design_method]]의 CLEAR로 선수 내용·연결·시각화·핵심 요약·마무리를 점검하고, 핵심 개념 묶음에는 4MAT의 What·How·Why·What if 질문을 붙인다. 이는 Ji가 강의 순서와 설명 방식을 구상할 재료이며, Agent의 최종 설명 선택이나 대본이 아니다.
5. **차이와 확인 사항:** 단순한 표현 차이는 각 출처 설명 옆에 남긴다. 사실·조건·레슨 경계가 충돌하면 Ref_No와 원문 줄을 붙여 `OPEN`에 적고, Agent가 원문으로 확인할 일과 Ji가 결정할 일을 구분한다. 필요한 원문이 빠졌다면 `topic_shaped`에 임의로 보태지 않고 `range_set_review.xlsx`와 `topic_raw`부터 바로잡는다.

| 출처의 관계 | 처리 기준 |
|---|---|
| 같은 설명의 반복 | 같은 주제 아래 출처별로 표시한다. 표현이 사실상 같아도 어느 Ref_No의 설명인지 남긴다. |
| 서로 보완하는 설명 | 조건·예외·예문을 출처별로 나란히 두고 관계를 적는다. 하나의 새 설명으로 합치지 않는다. |
| 원인·사실이 충돌하는 설명 | 서로 다른 주장을 출처와 함께 보이고, 확인되지 않은 차이는 `OPEN`에 남긴다. |
| Ji의 확정 경계와 어긋나는 설명 | 해당 원문과 경계의 차이를 표시한다. 경계를 바꿔야 한다면 Ji의 판단을 받는다. |

## 필요한 파일과 형식

| 파일 | 역할과 생성 시점 | 형식 |
|---|---|---|
| `03_topic_shaped/topic_shaped_plan.md` | 이 문서. 작업 기준의 단일 출처 | 진입 조건, 주제별 정리 방법, 파일 형식, 완료 검사 |
| `03_topic_shaped/03_topic_shaped.md` | 첫 레슨 산출물을 만들 때 필요한 폴더 index | 폴더 역할 한 문장과 이 계획, tracking, 레슨 파일의 경로 규칙을 가리키는 짧은 지도. 판단 내용이나 레슨 목록을 복사하지 않음 |
| `03_topic_shaped/<레벨>/<레슨 폴더>/<레슨 ID>_topic_shaped.md` | 진입 조건을 통과한 레슨마다 한 개 | 아래 형식. 원문 전문을 다시 붙이지 않고 Ref_No·원문 줄로 각 설명을 가리킴 |
| 기존 `lesson_spec_tracking.xlsx` | 레슨별 공식 진행 상태 | `레슨진행`의 기존 `status`, `작업일자`, `topic_shaped 경로`, `다음 조치`와 `작업이력`을 갱신. 새 시트나 별도 판정 XLSX는 만들지 않음 |

레슨별 파일의 기본 형식은 다음과 같다. 표와 주제 절의 행 수는 레슨 내용에 따라 늘린다.

```markdown
---
lesson_id: "<레슨 ID>"
stage: "topic_shaped"
---

# <레슨 ID> topic_shaped

## 입력과 확정 경계
- V7 레슨 제목: ...
- 경계 결정: [[range_set_review.xlsx]]의 해당 레슨 `Ji feedback`
- 원문 발췌: [[<레슨 ID>_topic_raw]]

## 주제별 출처 설명 정리
### 1. <설명 대상>
- 이 주제에서 학생이 이해할 질문: ...

| 출처·원문 줄 | 무엇을 설명하는가 | 어떻게 설명하는가: 비유·예문·조건·예외 | 다른 출처와의 관계·차이 |
|---|---|---|---|
| [<Ref_No · 줄>](vscode://file/<실제 raw 절대경로>:<범위 시작줄>:1) | ... | ... | ... |

## 강의 구조 구상용 배열
- Skeleton: <레슨의 큰 그림과 관련 주제 절>
- Flesh: <큰 그림에 붙는 주제 절의 논리적 순서>
- CLEAR 점검: <Calibrate · Link · Envision · Abstraction · Repeat에서 필요한 메모>
- 핵심 개념 묶음별 4MAT 질문: <What · How · Why · What if와 관련 주제 절>
- Ji가 구상할 설명 방식·영상 순서: <미정 또는 Ji 메모>

## 사용구간 정리 위치 확인
| 구간 ID | 정리한 주제 절·원문 줄 | 빠진 내용·확인 사항 |
|---|---|---|
| [<레슨 ID + Ref_No + 구간 순번>](vscode://file/<실제 raw 절대경로>:<범위 시작줄>:1) | 1 · [<원문 줄>](vscode://file/<실제 raw 절대경로>:<범위 시작줄>:1) | 없음 / ... |

## OPEN과 Ji 검토
- Ji가 정할 내용: <없음 또는 근거와 선택지>
- Agent가 확인할 사항: <없음 또는 확인할 원문·사실>
- Ji가 강의 구조를 구상할 때 볼 내용: <관련 주제 절·출처 차이·시각화 후보>
```

`사용구간 정리 위치 확인`에는 XLSX의 사용 구간마다 적어도 한 행을 둔다. 하나의 구간에 소주제가 여러 개면 같은 구간 ID를 여러 행에 쓰고 내부 줄을 밝혀 누락을 확인한다. 이 표는 원문의 정리 위치를 확인할 뿐 채택·비채택을 판정하지 않는다. Ji Draft만 있는 레슨은 억지로 출처 비교를 만들지 않고 내부 주제와 설명 방식을 정리한다.

줄 이동 링크에는 Windows에 설치된 VS Code의 `vscode://file/` 형식을 쓴다. `Ref_No`가 가리키는 **실제 raw 사본의 절대경로**와 범위의 시작 줄을 넣고, 경로의 공백·한글·`#` 같은 문자는 URL 형식으로 인코딩한다. `339~352`처럼 범위가 적혀 있으면 클릭 시 339줄을 연다. 링크를 만들기 위해 읽기 전용 raw에 제목이나 블록 ID를 추가하지 않는다.

## 완료 검사와 다음 단계

- 모든 사용 구간이 주제 절과 정리 위치 확인표에 나타나고, 각 설명·비유·예문에 Ref_No와 원문 줄이 붙어 있다. 단독 출처, Ji Draft 전체 발췌, 출처 간 차이도 빠지지 않는다.
- 모든 출처·줄 링크를 눌러 매핑된 raw 사본과 해당 범위의 시작 줄이 열리는지 확인한다. 여러 범위가 있는 표기는 각 링크를 따로 확인한다.
- 주제 배열이 Ji의 확정 경계를 지키며 Skeleton → Flesh 흐름으로 읽힌다. CLEAR와 4MAT 질문은 필요한 개념에 연결하되 출처 하나를 최종 설명으로 고르지 않는다.
- 원문 누락·경계 오류·사실 충돌처럼 진행을 막는 `OPEN`을 해결하고 위 정리를 마치면 tracking을 `topic_shaped`로 올려 파일 경로와 작업 근거를 `작업이력`에 남긴다. Ji가 여러 설명을 어떻게 조합할지는 이 단계의 완료 조건이 아니다.
- 다음 `lesson_spec`에서는 Ji가 이 정리를 보고 정한 설명 범위·구조를 `GOAL`, `SKELETON`, `TEACHING_POINTS`, `NEW`, `PREREQ`, `BUDGET`, `OUT_OF_SCOPE`, `SOURCES`, `OPEN` 등에 반영하고 검증한다. `OUTLINE`과 `DRAFT`의 대본 작업은 그다음 단계다.
