> 새 vault로 옮긴 뒤 **에이전트 지침 체계 전체를 다시 세운 날.**

> **확정된 것이 아니다.** Ji의 검토를 거쳐 계속 수정된다.

---

## 이 날의 문제 인식

새 vault에는 문서가 있긴 했지만 **"index 문서"와 "본문 문서"가 섞여 있었다.** `_about.md`에는 브랜드 본문이, `03_tech.md`에는 기술 스택 본문이, `02_course_creation.md`에는 이전 vault의 ACTION_PLAN 복사본이 들어 있었고 `01_raw.md`와 `04_marketing.md`는 0줄이었다. 같은 사실이 여러 문서에 흩어져 있어 에이전트가 무엇을 근거로 삼아야 할지 알 수 없는 상태였다.

그래서 이 날의 작업 방향을 하나로 잡았다. **폴더 index는 지도로만 쓰고, 실제 내용은 별도 문서에 두어 Single Source of Truth를 만든다.**

## CLAUDE.md에 적용한 지침 (6개 문서 종합)

`03_tech/01_CLAUDE.md`의 6개 문서를 읽고 공통 결론만 뽑아 적용했다.

| 지침 | 적용 방식 |
|---|---|
| 200줄 이하 | 172줄. §11에 상한과 초과 시 처리법을 규칙으로 박음 |
| 검증 가능한 구체적 규칙 | 모호한 문장 전부 제거. Hard Stops 6개는 판정 가능한 문장으로만 |
| 중요한 것은 맨 위 | Hard Stops를 §2로, Ji 소통 방식을 §3으로 |
| Progressive Disclosure | §4 라우팅 표가 핵심. 내용을 담지 않고 어느 index를 열지만 지정 |
| 도메인 용어 정의 | §9. Ji가 만든 용어 8개 |
| 검증 방법 제공 | §7. 코드가 아니므로 테스트 명령 대신 경로·수치·출처·중복 자가 검증으로 치환 |
| Karpathy 4원칙 | §6에 vault 맥락으로 번역 |

**적용하지 않은 것**: `/init` 자동 생성(비권장), `.claude/rules/`와 hooks(현재 규칙 양에 비해 과잉), `@import`(index 라우팅으로 이미 해결됨).

## Ji의 피드백과 반영

1. **"비전공자인 나에게 tech를 어떻게 소통할지 남겨달라"** → §3-2를 독립 절로 확장. 코드 문법을 가르치지 말 것, 역할·이유·원리 3가지를 줄 것, 4MAT 적용 표, 추가 규칙 4개(용어는 나오는 자리에서 정의 / 선택지는 trade-off를 일상 언어로 / 에러는 메시지 대신 무엇이 왜 막혔는지 먼저 / 이미 아는 용어는 반복 설명 금지).
2. **"long-term purpose와 short-term goal을 구분하라"** → §1을 둘로 분리. long-term은 "사업 운영의 기반이 되는 인프라이자 계속 자라는 AI Second Brain", short-term은 "강의 Draft 200개 생산 라인". **"당장의 산출물보다 구조와 기록을 지키는 것이 우선한다"**는 판단 기준을 덧붙임.
