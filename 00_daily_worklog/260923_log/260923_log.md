## workflow를 바꾼 이유

- concept index의 원래 목적은 레슨별로 가르칠 주제 범위를 정하는 것이었다.
- 하지만 레슨별 자료 매핑과 Ref_No는 이미 완료되어 있었다.
- 자료마다 등장하는 개념을 Agent가 분류하면, 무엇을 독립 개념으로 볼지와 어느 레슨에 쓸지를 추측해야 하는 모호한 판단이 많았다.
- 지금 필요한 판단은 개념 목록이 아니라, 각 레슨에 매핑된 자료 전체에서 실제로 가르칠 teaching point를 종합하고 우선순위를 정하는 일이었다.
- 같은 원본 자료가 여러 레슨에 쓰인 경우에는 레슨별로 사용할 원문 구간만 먼저 Ji가 확인하면 된다. 그래서 concept index는 제외하고, 중복 자료 선별표를 첫 관문으로 바꿨다.
- 원본 자료의 최종 사용 범위를 정하는 `range_set`과 그 이후 `topic_raw`, `topic_shaped`는 이 목적에 여전히 필요하므로 유지했다.

## 강의 대본 제작 workflow 변경

- `course_plan_update.md`를 만들어 기존 workflow에서 concept index만 제외했다.
- 레슨별 자료 매핑과 Ref_No의 정본은 기존 index xlsx로 유지한다.
- 중복 자료는 JSON보다 먼저 `duplicate_material_selection.xlsx`에서 Ji가 직접 확인한다.
- Ji의 최종 선택 뒤에만 JSON의 종류·필드·저장 위치·Markdown 산출물 연결 방식을 함께 결정한다.
- 이후 단계는 기존처럼 `range_set → topic_raw → topic_shaped → lesson_spec → OUTLINE → DRAFT` 순서로 유지한다.
- Amira의 같은 세션 Script·통합본·녹화본은 같은 수업의 여러 기록으로 보며, 독립 출처 여러 개로 세지 않는다.

## 중복 자료 선별표 구축

- 6개 기존 index에서 파일명 기준으로 중복 매핑 후보를 찾아 266개 원본 자료 묶음과 888개 레슨별 사본 행을 기록했다.
- `duplicate_material_selection.xlsx`를 Ji가 만든 `duplicate_material_update.xlsx`의 12칼럼 형식으로 맞췄다.
- 같은 DMS 묶음의 행은 같은 연한 배경색으로 표시해 한 원본 자료가 어느 레슨에 쓰이는지 바로 비교할 수 있게 했다.
- 원문을 아직 읽지 않은 행은 추측하지 않고 `미검토`로 유지했다.

## DMS-0001~0010 선별안

- Amira 세션 01, 03, 04, 05-06, 07의 통합본과 Script를 읽어 DMS-0001~0010의 42개 레슨 사본에 발췌 내용·원문 구간·제외 내용·제외 이유를 작성했다.
- DMS-0001은 Ji가 직접 작성한 결과이므로 변경하지 않았다.
- DMS-0002~0010의 39개 행은 DMS-0001과 같은 상세 형식으로 재작성하고 상태를 `Agent 제안 완료`로 유지했다.
- Ji 검토 의견·최종 선택 칼럼은 Ji 확인을 위해 비워 두었다.
