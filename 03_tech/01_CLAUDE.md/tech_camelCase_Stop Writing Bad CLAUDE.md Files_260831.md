## 핵심 요약
- `CLAUDE.md`는 300줄 이하(권장 150~200줄)로 짧고 간결하게 유지해야 모델의 지시 이행 능력이 저하되지 않는다.
- 프레임워크, 핵심 명령어, 프로젝트 특유의 주의사항(Caveats) 세 가지만 포함하는 것이 가장 효율적이다.
- 상세한 규칙이나 스키마 정보는 `Progressive Disclosure` 원칙에 따라 별도 파일로 분리하고, `.claude/rules` 설정을 통해 필요한 컨텍스트만 동적으로 로드한다.

## 적용 지식

### CLAUDE.md의 역할과 최적의 크기 [01:18]
`CLAUDE.md`는 클로드(Claude)가 세션을 시작할 때 자동으로 읽는 마크다운 파일로, 프로젝트별 특정 지침을 제공한다. 하지만 대규모 언어 모델(LLM)이 일관되게 따를 수 있는 지침의 수는 제한적이다. `Claude Opus 4.5`와 같은 강력한 모델도 약 150~200개의 지침까지만 높은 일관성을 유지하며, 그 이상을 넘어가면 모든 지침에 대한 응답 품질이 전반적으로 저하된다. 특히 `Claude Code` 자체의 시스템 프롬프트가 이미 약 50개의 지침을 점유하고 있으므로, 사용자가 작성하는 `CLAUDE.md`는 가능한 한 짧게 유지해야 한다.

### AI를 이용한 자동 생성의 위험성 [02:45]
`/init` 명령어를 사용하여 AI가 `CLAUDE.md`를 생성하게 하는 것은 권장되지 않는다. AI가 생성한 텍스트는 지나치게 장황(Verbose)하며, 모호하거나 불필요한 지침을 포함하는 경우가 많다. 잘못된 코드 한 줄은 해당 위치에만 영향을 주지만, 잘못 작성된 `CLAUDE.md` 한 줄은 클로드가 수행하는 모든 프롬프트와 액션에 부정적인 영향을 미쳐 전체적인 성능을 떨어뜨린다.

### 코드 스타일 지침 제외 및 자동화 [05:41]
들여쓰기나 따옴표 사용법 같은 코드 스타일 지침을 `CLAUDE.md`에 직접 적는 것은 비효율적이다. 클로드는 이미 기존 코드에서 스타일을 유추하는 능력이 뛰어나며, 이러한 세부 지침은 모델의 지시 이행 용량을 낭비하게 만든다. 대신 린터(Linter)나 포매터(Formatter)를 사용하고, 클로드에게 이를 실행하도록 지시하는 것이 낫다.

`.claude/settings.json` 파일을 생성하여 `post-tool-use` 훅(hook)을 설정하면 파일 업데이트 후 자동으로 포매팅 명령을 실행할 수 있다.

```json
{
  "hooks": {
    "post-tool-use": "npm run lint:fix"
  }
}
```

### CLAUDE.md의 3대 핵심 구성 요소 [06:18]
효율적인 `CLAUDE.md` 작성을 위해 다음 세 가지 요소만 포함하는 것이 좋다.

1.  **프로젝트 개요 (One-liner):** 프로젝트의 성격과 기술 스택을 한 줄로 요약한다. (예: "Next.js로 구축된 고객 결제 포털", "Astro 기반 문서 사이트")
2.  **핵심 명령어 (Key Commands):** 빌드, 테스트, 린트 등 일상적인 작업에 필요한 주요 `bash` 명령어를 나열한다.
3.  **주의사항 (Caveats):** 코드만 봐서는 알 수 없는 프로젝트 특유의 경고 사항을 적는다. (예: "Prisma 스키마를 직접 수정하지 말고 `npm run db generate`를 실행할 것", "이미지는 커밋 전 최적화 필수")

### 점진적 노출(Progressive Disclosure)과 규칙 분리 [08:54]
데이터베이스 스키마나 특정 에지 케이스(edge case)처럼 항상 필요하지 않은 정보는 별도 파일로 분리한다. 예를 들어 `docs/schema.md`에 상세 내용을 적고 `CLAUDE.md`에서는 참조 링크만 남긴다.

더 정교한 방법은 `.claude/rules` 폴더를 사용하는 것이다. 파일 상단에 `paths` 설정을 포함한 `YAML frontmatter`를 작성하면, 클로드가 특정 경로의 파일을 작업할 때만 해당 규칙을 로드하도록 제한할 수 있다.

```markdown
---
paths:
  - "src/api/**/*.ts"
---

# API Development Rules
- 모든 API 엔드포인트는 입력 유효성 검사를 포함해야 함.
- 표준 에러 응답 형식을 사용할 것.
```

### 지침의 우선순위와 강조 기법 [10:18]
클로드는 프롬프트의 양 끝(시작과 끝)에 있는 지침을 더 잘 기억하는 경향이 있다. 따라서 가장 중요한 지침은 `CLAUDE.md` 상단에 배치해야 한다. 또한, `IMPORTANT`, `YOU MUST`와 같이 대문자를 사용하거나 느낌표를 사용하여 강조하는 것이 모델의 주의를 끄는 데 도움이 된다고 `Anthropic` 문서에서 명시하고 있다.

### 워크플로우 통합 및 유지보수 [11:40]
`CLAUDE.md`는 살아있는 문서여야 한다. 코드 리뷰 중 반복되는 실수를 발견하면 즉시 업데이트해야 한다. `Claude GitHub Action`을 설치하면 풀 리퀘스트(PR)에서 클로드를 태그하여 지침을 추가하도록 시킬 수 있다.

```text
@claude add to CLAUDE.md to never use enums, always prefer literal unions
```

### CLAUDE.md 배치 위치 및 우선순위 [12:58]
클로드는 현재 디렉토리뿐만 아니라 상위 디렉토리의 `CLAUDE.md`도 자동으로 검색한다.
- **Root 디렉토리:** 일반적인 프로젝트 루트에 배치.
- **모노레포(Monorepo):** 루트와 하위 프로젝트 디렉토리에 각각 배치하여 공통 규칙과 개별 규칙을 병합 적용 가능.
- **CLAUDE.local.md:** 공유 저장소에 커밋하고 싶지 않은 개인적인 설정(개인 샌드박스 URL 등)을 위해 사용하며, `.gitignore`에 추가하여 관리한다.
- **~/.claude/CLAUDE.md:** 사용자의 홈 디렉토리에 배치하면 모든 프로젝트 세션에 전역적으로 적용된다.

## 주의사항
- **지침 한계:** `CLAUDE.md`가 너무 길어지면 클로드가 지침을 무시하거나 응답 품질이 급격히 떨어진다. 300줄 이하를 엄수해야 한다.
- **시스템 리마인더:** `Claude Code`는 시스템적으로 `CLAUDE.md`의 내용이 관련이 없을 수도 있다는 경고를 모델에게 보낸다. 따라서 지침이 작업과 밀접하게 관련되어 있음을 명확히 해야 한다.
- **정기 감사:** AI 모델의 동작 방식과 `Claude Code`의 기능은 수시로 변경되므로, 최소 월 단위로 `CLAUDE.md`를 검토하고 업데이트하는 것이 권장된다.
