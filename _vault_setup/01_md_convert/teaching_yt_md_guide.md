# teaching_yt_md_guide.md

> Teaching 영상 전용 변환 규칙서. 설명법에 관한 영상을 강의 제작에 다시 쓸 수 있는 지식 문서로 바꿀 때 따른다.
> 이 문서는 변환 기준이다. Teaching 전용 변환 스크립트나 영상 변환 결과물이 이미 있다는 뜻은 아니다.
> 작성: 2026-10-20

---

## 1. 목적과 경계

`teaching_yt_md_convert.xlsx`에서 Ji가 고른 영상을 보고, **학습자가 이해하도록 설명하는 방법**을 `.md`로 정리한다. 완성된 문서는 `05_teaching/`에서 찾아 쓸 교수법 자료가 된다.

이 자료의 쓰임은 두 단계다.

- **OUTLINE:** 이번 레슨에서 어떤 순서로 설명하고, 어떤 비유·대조·질문·이해 확인이 필요한지 판단할 때 참고한다.
- **Draft:** OUTLINE에서 선택한 방법을 학습자에게 말하는 영어 대사와 한국어 예문에 자연스럽게 구현할 때 참고한다.

Teaching 영상은 **설명 방식의 근거**다. 한국어 문법, 표현의 뜻, 예문 사용 조건을 확정하는 근거로 쓰지 않는다. 그 내용은 Ji의 기존 강의 자료와 Ji가 정한 방향에서 확인한다. 영상에서 소개한 방법도 모든 레슨에 적용할 고정 양식으로 만들지 않는다.

변환 단계에서는 영상의 주장과 실제 시범을 정확히 기록한다. Korean With Ji에 맞는 채택 여부와 구체적인 대사 문장은 해당 레슨의 OUTLINE·Draft 작성 시 판단한다. Ji의 검수를 거치기 전 변환 결과를 확정된 교수법으로 취급하지 않는다.

## 2. 입력과 상태

정본 목록: `_vault_setup/01_md_convert/teaching_yt_md_convert.xlsx`

| 컬럼 | 사용법 |
|---|---|
| `자료구분` | Teaching 대상인지 확인한다. |
| `채널` | 출처와 파일명에 사용한다. |
| `저장위치` | 검수 후 최종 위치를 확인한다. 현재 지정된 값은 `05_teaching`이다. |
| `영상 타이틀` | 원본 제목과 파일명에 사용한다. |
| `링크` | 원본 영상을 열고 중복 URL을 확인한다. |
| `변환완료여부` | `X`만 처리 대상으로 삼는다. |

상태값은 `X` = 변환 대기, `O` = 형식·근거 검증 통과, `F` = 검증 실패 및 사람 검토 대기로 사용한다. `O`는 Ji의 내용 승인이나 최종 채택을 뜻하지 않는다. 빈칸은 `X`로 간주하지 않는다. 실제 변환을 실행하기 전에는 파일 사용 상태와 대상 행을 다시 확인한다. 목록은 원본 그대로 유지하고, 변환 실행이 별도로 승인되기 전에는 상태값을 바꾸지 않는다.

같은 URL이 여러 행에 있으면 영상을 한 번만 변환한다. 행마다 `저장위치`가 다르면 출력 위치를 추측하지 말고 Ji에게 확인한다.

## 3. 결과물 위치와 파일명

변환 결과는 Ji의 검토 전까지 다음 대기소에 둔다.

- 검증 통과 예정 경로: `_vault_setup/01_md_convert/result_check/convert_O/`
- 검증 실패 예정 경로: `_vault_setup/01_md_convert/result_check/convert_F/`

**2026-10-20 확인 결과, 두 대기소는 실제 폴더가 없다.** 이후 변환을 시작하기 전에 경로를 다시 확인하고, 필요한 폴더 생성 범위를 Ji에게 먼저 제시한다. 검증 실패 파일도 삭제하지 않고 보관해 Ji가 확인할 수 있게 한다. Ji가 검수한 파일만 목록의 `저장위치`에 따라 `05_teaching/`으로 옮긴다. 자동으로 최종 위치에 넣지 않는다.

파일명: `teaching_[채널]_[영상제목]_[변환일].md`. 변환일은 실행일의 `YYMMDD`이며 업로드 날짜와 구분한다. Windows 금지문자 `\ / : * ? " < > |`는 공백으로 바꾸고, 연속 공백을 합친다. 파일명이 길면 제목 부분을 줄이되 채널·변환일은 보존한다.

## 4. 한 영상의 `.md` 구조

```markdown
# [채널] | [영상 제목]

## Metadata
- **채널:**
- **URL:**
- **원본 제목:**
- **영상 길이:**
- **업로드 날짜:**
- **변환일:**

## 핵심 요약
[영상이 실제로 제시한 설명 원리와 결론을 3~5문장으로]

## 설명 방법
### [방법을 알 수 있는 제목] [MM:SS]
[언제 쓰는지, 어떤 순서로 하는지, 왜 효과가 있다고 설명하는지]

## 영상 속 사례
[발표자가 실제로 보여준 설명 전후, 비유, 질문, 시각 자료 중 방법을 이해하는 데 필요한 사례]

## 적용 조건·한계
[영상에서 밝힌 대상, 전제, 예외, 실패 사례가 있을 때만]

## 확인 필요
[발화·화면·출처가 불명확해 Ji의 확인이 필요한 내용이 있을 때만]
```

`영상 길이`나 `업로드 날짜`를 확인할 수 없으면 임의로 채우지 않고 `미확인`으로 적는다. 빈 `적용 조건·한계`와 `확인 필요` 섹션은 만들지 않는다. 설명 방법이 여러 개면 방법별 소제목을 만든다. 1시간 이상 영상의 위치는 `[H:MM:SS]`로 쓴다.

## 5. 내용 추출 규칙

1. **영상 전체의 말과 화면을 함께 확인한다.** 말로 설명한 순서와 화면의 도표·손짓·예시가 함께 의미를 만들면 둘 다 반영한다. 화면에만 나온 핵심 문구나 대비도 놓치지 않는다.
2. **방법이 작동하는 장면을 남긴다.** ‘쉽게 설명하라’ 같은 구호만 적지 않는다. 발표자가 무엇을 먼저 보여주고, 어떤 질문이나 예시로 이어가며, 이해 여부를 어떻게 확인하는지 재현 가능한 수준으로 적는다.
3. **주장과 사례를 구분한다.** 발표자가 효과를 주장한 것인지, 영상에서 시범을 보인 것인지 구분해 쓴다. 연구 근거나 성과 수치를 영상 밖에서 가져와 덧붙이지 않는다.
4. **원래 맥락을 보존한다.** 발표 대상, 학습자의 출발점, 설명 주제, 필요한 시간이나 조건이 드러나면 함께 적는다. 일반 대중에게 설명하는 방법을 성인 한국어 학습자에게 곧바로 효과가 입증된 방법처럼 쓰지 않는다.
5. **출처를 되찾을 수 있게 한다.** 주요 방법과 사례의 시작 위치를 제목 또는 본문에 남긴다. 타임스탬프는 실제 영상에서 확인한다. 확인하지 않은 위치를 추정하지 않는다.
6. **잡음을 덜어낸다.** 인사, 광고, 구독 요청, 내용 없는 반복은 제외한다. 다만 설명법을 보여주는 의도적인 반복과 앞뒤 대비는 보존한다.
7. **원문 언어를 왜곡하지 않는다.** 내부 설명은 한국어로 쓰되, 방법의 영문 이름과 의미를 결정하는 짧은 표현은 원어를 병기한다. 긴 대사나 전문 받아쓰기는 넣지 않는다.

영상에 없는 한국어 예문, Ji의 강의에 맞춘 새 비유, 최종 대사, 채택·비채택 판단은 이 문서에 만들지 않는다. 필요해 보이는 적용 아이디어가 있더라도 원본 내용처럼 섞지 말고 OUTLINE 작성 단계에서 별도로 검토한다.

## 6. 검증과 Ji 검수

변환 직후 다음을 확인한다.

- 목록의 URL·채널·제목과 `.md`의 Metadata가 일치한다.
- 주요 방법·사례마다 실제 영상에서 확인한 위치가 있다.
- 설명 순서, 시범, 적용 조건이 요약 과정에서 빠지거나 뒤바뀌지 않았다.
- 말과 화면이 충돌하거나 읽기 어려운 부분은 단정하지 않고 `확인 필요`에 남겼다.
- 발표자의 주장과 변환자의 해석이 섞이지 않았다.
- Korean With Ji의 문법 사실이나 최종 대사를 영상에서 임의로 만들어 내지 않았다.
- 파일명과 검토 대기 위치가 규칙에 맞는다.

검증을 통과해 `O`가 되어도 Ji가 자료의 신뢰도와 실제 활용 가치를 검수한다. Ji는 자료 선택·검수·방향 결정을 맡고, 변환과 반복 확인은 에이전트가 한다. 첫 영상 한 편을 시범 변환해 Ji의 검수를 받은 뒤 나머지에 적용한다.

## 7. 실행 준비 상태

현재 확인된 것은 대상 목록과 이 가이드의 작성 범위다. **Teaching 전용 변환 스크립트와 검토 대기 폴더는 아직 확인되지 않았다.** 이 가이드를 작성했다고 영상 변환이 실행되거나 OUTLINE·Draft 지시서에 자동으로 연결되는 것은 아니다. 이후 실행 단계에서 도구, 비용, 처리 방식, 폴더 생성, 기존 지시서 연결을 각각 실제 상태에 맞춰 확인한다. Tech 영상용 프롬프트와 코드·명령어 중심 검증 규칙을 Teaching 영상에 그대로 적용하지 않는다.
