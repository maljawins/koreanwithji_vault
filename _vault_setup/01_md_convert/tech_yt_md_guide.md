# tech_yt_md_guide.md

> Tech 트랙 전용 규칙서. 이 파일 하나만 읽고도 tech 영상 변환 작업이 가능하도록 작성됨.
> 한국어 강의 영상 변환은 이 파일이 아니라 `korean_yt_md_guide.md`를 따른다.
> 두 트랙은 **스크립트까지 완전히 분리**되어 있다. 서로 참조하지 않고 코드도 공유하지 않는다.
> 최종 갱신: 2026-09-03

---

## 1. 프로젝트

`tech_yt_md_convert.xlsx`에 나열된 YouTube 영상을 시청·이해해서 .md 파일로 변환하는 작업.

**변환된 .md의 목적**
AI, 코딩, 개발, vault 운영 관련 영상을 Claude가 읽고 **실제 작업에 적용**하기 위한 지식 문서. Claude가 이 vault의 구조를 설계하거나 스크립트를 작성할 때 참고 근거로 쓴다.

**따라서 tech .md는 "영상 기록"이 아니라 "실행 가능한 지식"이다.**
유튜버의 잡담, 인사, 구독 유도, 중복 반복 설명은 전부 버린다. 남기는 것은 결론, 절차, 설정값, 명령어, 그리고 "언제 이 방법을 쓰고 언제 안 쓰는가"의 판단 근거다.

**왜 이렇게 하는가**
tech .md는 나중에 에이전트가 검색해서 꺼내 쓰는 문서다(RAG = 질문할 때마다 창고를 뒤져 답을 찾아오는 방식). 창고에 잡담과 규칙이 섞여 있으면 검색 결과에 쓰레기가 딸려 오고, 그만큼 에이전트의 판단이 흐려진다. 정보량이 아니라 신호 대 잡음 비율이 이 문서의 품질 기준이다.

## 2. 트랙 경계

| 항목 | Tech 트랙 (이 문서) | Korean 트랙 |
|---|---|---|
| 스크립트 | `tech_yt_md_pipeline.py` | `kor_yt_md_pipeline.py` |
| 입력 xlsx | `tech_yt_md_convert.xlsx` | `korean_yt_md_convert.xlsx` |
| 파일명 접두어 | `tech_` | `kor_` |
| 결과물 소비자 | Claude (vault 운영·코드 작성) | Ji + Claude (강의 Draft 원료) |
| 영상 다운로드 화질 | **1080p** | 480p |
| Whisper 유도 프롬프트 | 영문 기술용어를 **영문으로** 받아쓰게 유도 | 한국어 단어를 **한글로** 받아쓰게 유도 |
| OCR 앵커 | 화면의 **영문** 용어·명령어·파일명 수집 | 화면의 **한글** 토큰 수집 |
| 본문 언어 | 한국어 + 영어 용어 병기 | 전부 영어 |
| Transcript | **없음** | 전문 보존 |
| 예문 형식 | 코드블록 (명령어·설정 원문) | 블록 인용 (한국어 예문 + 영어 해석) |
| 섹션 타임스탬프 | **있음** (근거 추적용) | 없음 |
| 정보 처리 | 압축 (잡음 제거) | 보존 (누락 금지) |

### 스크립트를 완전히 분리하는 이유

두 트랙은 4단계(Whisper 받아쓰기)부터 갈라진다. Gemini 프롬프트만 다른 게 아니다.

korean 트랙의 Whisper 유도 프롬프트는 "한국어 단어는 로마자가 아니라 한글로 받아쓸 것"을 지시한다. **이 지시가 tech 영상에 걸리면 `Agent`가 `에이전트`로, `MCP`가 `엠씨피`로 기록된다.** tech 트랙에 필요한 것과 정확히 반대다. OCR 앵커 수집도 마찬가지다. korean은 화면의 한글만 모으는데, tech 영상 화면의 정답지는 영문 명령어와 파일명이다. 커버리지 검증도 korean은 한글 문자열이 출력에 들어갔는지 보는데, tech 문서에는 한글 용어가 거의 없다.

그래서 두 스크립트는 공통 모듈 없이 각자 완결된 파일로 둔다. korean 작업과 tech 작업을 동시에 돌릴 일이 없으므로 파일이 갈라져 있어 생기는 불편이 없고, 한쪽을 고치다 다른 쪽이 오염될 위험이 구조적으로 사라진다.

**중요**: `tech_yt_md_pipeline.py`는 `kor_yt_md_pipeline.py`를 복사해서 고친 것이 아니다. 위 한국어 전용 지점이 1,000줄 넘는 코드에 흩어져 있어 눈으로 걷어내면 반드시 빠뜨린다. 빠뜨려도 에러가 안 나고 결과만 조용히 나빠진다. 반대 방향도 같다. 한쪽 스크립트를 다른 쪽에 복사하지 않는다.

## 3. 입력

**파일**: `C:\vault\Koreanwithji_vault\_vault_setup\01_md_convert\tech_yt_md_convert.xlsx`

**컬럼**

| 컬럼 | 내용 | 비고 |
|---|---|---|
| 자료구분 | `Tech` 고정 | |
| 채널 | 유튜브 채널명 | 파일명에 사용 |
| 목적 | 이 영상을 왜 보는가 | 예: `CLAUDE.md 작성`, `MEMORY 관리`, `Vault 세팅` |
| 영상 타이틀 | 원본 제목 | 파일명에 사용 |
| 링크 | youtu.be URL | |
| 변환완료여부 | 상태값 | X / O / F |

**상태값 3단계** (korean 트랙과 동일하게 통일)

- `X` = 미변환. **스크립트 처리 대상은 X인 행뿐이다.**
- `O` = 변환 완료
- `F` = 검증 실패. `_vault_setup\01_md_convert\result_check\convert_F\` 보관, 사람 검토 대기

변환 성공 시 X → O, 검증 실패 시 X → F로 자동 갱신 후 xlsx 저장. O와 F는 재실행 시 건너뛴다.

> 주의: 현재 이 컬럼이 전부 공란이다. 파이프라인 첫 실행 전에 처리 대상 행을 `X`로 채워야 한다. 공란은 X로 간주하지 않는다(오작동 방지).

## 4. 출력

### 저장 위치

> 2026-08-31 개정: 검증 통과/실패를 폴더로 분리했다. 이전에는 `01_inbox\` 평면 저장 + 실패만
> `01_inbox\convert_fail\`로 뺐는데, 지금은 성공도 실패도 각자 전용 폴더로 들어간다.
> 2026-09-03 개정: `result_check\`를 `01_inbox\`에서 `_vault_setup\01_md_convert\` 밑으로 옮겼다.

```
검증 통과: C:\vault\Koreanwithji_vault\_vault_setup\01_md_convert\result_check\convert_O\
검증 실패: C:\vault\Koreanwithji_vault\_vault_setup\01_md_convert\result_check\convert_F\
```

각 폴더 안에서는 평면 저장이다. `convert_O`, `convert_F` 밑에 추가로 하위 폴더를 만들지 않는다.

`result_check`는 AI 산출물 중 "검토 대상"을 성공/실패로 갈라놓은 대기소다. 변환된 tech .md는 `convert_O`에 떨어지고, Ji가 읽은 뒤 직접 최종 위치로 옮긴다. **스크립트가 `02_tech\` 등 다른 곳에 직접 저장하지 않는다.**

### 최종 분류

`convert_O\`, `convert_F\`는 어디까지나 검토 대기소다. Ji가 파일을 열어 내용을 확인한 뒤 **수동으로**
`03_tech\` 밑 주제별 폴더(예: `01_CLAUDE.md_작성가이드\`, `02_MEMORY_관리\`)로 옮긴다. 스크립트는
이 이동을 절대 자동으로 하지 않는다 — `convert_O`에 저장까지가 스크립트의 역할이고, 그다음 "이 결과물을
최종적으로 어디에 둘지"는 항상 사람의 판단이다. `convert_F`로 간 파일도 마찬가지로, Ji가 품질을 직접
보고 괜찮다고 판단하면 `03_tech\`로 옮길 수 있다(섹션 4 "왜 실패한 파일까지 굳이 저장하는가" 참고).

### 파일명 규칙

```
tech_[채널]_[영상제목]_[변환일].md
```

- `변환일` = **변환을 실행한 날짜** (YYMMDD). 영상 업로드 날짜를 파일명에 쓰는 것은 **절대 금지**.
- 예: `tech_짐코딩_CLAUDE.md 하나로 AI 코딩 품질이 3배 달라집니다_260830.md`
- 예: `tech_jaredrhod_How I Set Up Obsidian with Claude Code_260830.md`

`tech_` 접두어는 필수다. `result_check\convert_O\`는 tech 트랙만 쓰고(korean 트랙은 별도 레슨 폴더로 바로 저장), `convert_F\`는 tech·korean 두 트랙이 같이 쓰는 폴더라 접두어가 있어야 골라낼 수 있다.

### 파일명 금지문자 처리

Windows 파일명에 다음 문자를 쓸 수 없다.

```
\ / : * ? " < > |
```

유튜브 제목에는 `|` 와 `?` 가 자주 들어간다. 처리 규칙:

1. 위 9개 문자를 **공백 1개로 치환**한다
2. 연속 공백은 1개로 합친다
3. 앞뒤 공백을 잘라낸다
4. 파일명 전체 길이가 200자를 넘으면 영상제목 부분을 잘라낸다 (접두어·날짜·확장자는 보존)

치환하지 않고 삭제하면 단어가 붙어버려 검색이 안 되므로 반드시 공백으로 치환한다.

### 검증 실패 파일

검증에 실패한 .md는 **절대 삭제하지 않는다.** 다음 위치에 원본 파일명 그대로 저장한다.

```
C:\vault\Koreanwithji_vault\_vault_setup\01_md_convert\result_check\convert_F\
```

접두어를 추가로 붙이지 않는다(파일명이 이미 `tech_`로 시작한다). xlsx 상태값은 F로 갱신한다.

**왜 실패한 파일까지 굳이 저장하는가**: 검증기는 `Agent`가 `에이전트`로 한 번 새어나간 것처럼, 본문
전체 품질과 무관한 사소한 흠 때문에도 F를 매긴다. 이런 결과를 버리면 Ji가 실제 결과물 퀄리티를 눈으로
확인할 방법이 없어진다. 그래서 검증 실패는 삭제·재작성 대상이 아니라 "기계적으로는 규칙 위반이지만
사람이 최종 판단해야 할 결과물"로 취급한다. Ji가 `convert_F`를 열어 보고 이 정도 흠은 괜찮다고 판단하면
그대로 최종 폴더로 옮기면 되고, 정말 문제라고 판단하면 재변환을 요청하면 된다.

## 5. .md 파일 구조

```
# [채널명] | [영상 제목]

## Metadata
(불릿 리스트)

---

## 핵심 요약
(3~5줄)

---

## 적용 지식

### [주제별 섹션명] [MM:SS]
(내용)

---

## 주의사항
(전제조건·한계·버전 의존성)
```

`## Transcript` 섹션은 **만들지 않는다.**

### Metadata 형식

불릿 리스트만 허용. 테이블 형식(`| Field | Content |`) 절대 금지.

```
- **채널:** 짐코딩
- **URL:** https://youtu.be/cZ8_Dkk_Ce0
- **Duration:** 14:22
- **Upload Date:** 2026-07-15
- **목적:** CLAUDE.md 작성
- **변환일:** 2026-08-30
```

`목적`은 xlsx의 `목적` 컬럼 값을 그대로 옮긴다. Upload Date는 Metadata에는 기록하되 파일명에는 쓰지 않는다.

### 핵심 요약

이 영상이 주장하는 것을 3~5줄로 압축한다. "무엇을 다루는 영상인가"가 아니라 **"이 영상의 결론이 무엇인가"**를 쓴다.

- (O): "CLAUDE.md는 짧을수록 좋다. 200줄 넘으면 모델이 중간 내용을 무시하기 시작하므로, 상세 규칙은 별도 파일로 빼고 CLAUDE.md에는 참조 링크만 남긴다."
- (X): "CLAUDE.md 작성 방법에 대해 설명하는 영상이다." (내용이 없음)

### 적용 지식

본문의 핵심. 주제별로 섹션을 나눈다.

- **섹션명**: 번호 prefix 금지. 주제를 설명적으로 표현한다.
  - (O): `### CLAUDE.md를 짧게 유지해야 하는 이유 [03:40]`
  - (X): `### 1. CLAUDE.md 작성법`
- **타임스탬프**: 섹션명 끝에 `[MM:SS]` 형식으로 해당 내용이 시작되는 시점을 붙인다. 나중에 사람이 원본 영상에서 근거를 확인할 수 있어야 하기 때문이다. 1시간 넘는 영상은 `[H:MM:SS]`.
- **본문**: 한국어 산문 서술체. 불릿 나열 금지.
  - 단, 명령어 목록·설정 항목·비교표처럼 본질적으로 리스트인 정보는 불릿·테이블 유지 가능.
- **실물은 코드블록**: 명령어, 설정 파일 내용, 폴더 구조, 프롬프트 예시는 반드시 코드블록에 **원문 그대로** 넣는다. 산문으로 풀어 쓰지 않는다.

  ````
  ```bash
  claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem ~/vault
  ```
  ````

- **Over-summarize 금지**: 영상에서 설명한 절차, 조건, 예외, 실패 사례를 빠짐없이 기술한다. 다만 같은 말을 반복하는 구간은 1회로 합친다.
- **가장 중요**: Claude가 이 .md 하나만 보고 영상 없이 그 방법을 **실제로 재현할 수 있는 수준**의 상세도를 요구한다.

### 주의사항

영상이 명시한 전제조건과 한계를 모은다. 영상에 없는 내용을 추측해서 쓰지 않는다.

- 필요한 버전·요금제·플랫폼 (예: "Claude Code 2.0 이상", "macOS 기준 경로")
- 안 되는 경우 (예: "팀 공유 vault에서는 이 방식이 충돌함")
- 발표자가 직접 언급한 실패·시행착오

해당 내용이 영상에 없으면 섹션 자체를 생략한다. 빈 섹션을 남기지 않는다.

### 쓰지 않는 것

- `이 vault에 적용 가능한가` 류의 판단 섹션. **변환을 실행하는 Gemini는 이 vault의 구조를 모른다.** 쓰게 하면 추측이 들어가고, 그 추측이 나중에 사실처럼 재인용된다. 적용 판단은 Claude가 이 .md를 읽고 그때 하는 것이지 변환 시점에 박아 넣는 것이 아니다.
- 영상에 대한 감상·평가 ("매우 유익한 영상이다")
- 구독·좋아요 유도, 광고, 협찬 고지, 인사말

## 6. 작성 언어 규칙

**본문은 한국어. 기술 용어는 영어 원어 병기.**

- 설명·서술은 한국어 산문으로 쓴다.
- 기술 용어 첫 등장 시 한글 + 영어 병기: `컨텍스트 창(context window)`, `토큰(token)`
- **명령어, 코드, 파일명, 폴더명, 설정 키, 옵션 플래그, 제품명은 영문 원문 그대로.** 번역·음차 절대 금지.
  - (O): `CLAUDE.md`, `MCP`, `/compact`, `npx`, `Claude Code`, `Agent`
  - (X): `클로드 점 엠디`, `엠씨피`, `컴팩트 명령어`, `클로드 코드`, `에이전트`

### Whisper 한글 음차 강제 교정 (**매우 중요**)

한국어 tech 영상의 최대 리스크다. Whisper는 한국어 발화 속 영어 기술용어를 **한글로 받아쓴다.**

| Whisper 출력 | 실제 |
|---|---|
| 에이전트 | Agent |
| 클로드 코드 | Claude Code |
| 엠씨피 | MCP |
| 깃허브 | GitHub |
| 커밋 | commit |
| 컨텍스트 윈도우 | context window |
| 서브에이전트 | subagent |

이대로 두면 나중에 에이전트가 `MCP`나 `Agent`로 검색해도 이 문서가 안 잡힌다. 문서가 있어도 없는 것과 같아진다.

**2단 방어**

1. **입력 단계**: `tech_yt_md_pipeline.py`의 Whisper 유도 프롬프트에 영문 기술용어 목록을 넣어, 받아쓰기 시점부터 영문으로 나오게 유도한다. (korean 스크립트의 "한글로 받아쓸 것" 프롬프트와 정확히 반대다.)
2. **출력 단계**: 화면 OCR에서 추출한 영문 문자열을 정답지로 삼아, 본문에 남은 한글 음차를 영문 원어로 강제 치환한다.

OCR에 근거가 없고 문맥상 영어 용어가 확실한 경우에도 영문으로 쓴다. 판단이 애매하면 `한글 음차(영문)` 형태로 둘 다 남긴다.

tech 영상은 화면에 코드·터미널·설정 파일이 그대로 뜨므로 OCR 정확도가 korean 트랙보다 높다. 이 점을 적극 활용한다.

## 7. 파이프라인 (기술 스택)

**코드**: `_vault_setup\01_md_convert\_scripts\tech_yt_md_pipeline.py`
**환경**: GPU RTX 4070 Laptop (8GB VRAM)
**합성 모델**: Gemini 3 Flash (`gemini-3-flash-preview`). 구형 2.5 아님.
**비용**: 스크립트 내 하드 상한 없음. 한도는 Google AI Studio 콘솔에서 관리. CostTracker가 누적 토큰·원화를 로그에 기록(모니터링용).
**병목**: 로컬 Whisper. 다운로드·OCR·Gemini는 동시 처리.

**핵심 원리**: 돈 드는 일(영상 보고 듣기)은 전부 로컬에서 무료로 처리하고, Gemini에는 "타임라인 텍스트 + distinct 프레임 이미지"만 보내 .md만 쓰게 한다. 영상 자체를 클라우드에 안 보내므로 비용이 예측 가능하고 Rate Limit 위험이 작다.

### 로컬 도구 (전부 무료)

- **yt-dlp** - **1080p** mp4 1개만 다운로드
  - korean 트랙(480p)과 다른 유일한 이유는 화면 글자다. tech 영상은 터미널 출력, 코드 에디터, 설정 파일이 화면에 뜨는데 480p에서는 글씨가 뭉개져 OCR과 Gemini가 둘 다 오인식한다. 명령어 한 글자가 틀리면 그 문서는 못 쓴다.
  - 대가: 다운로드 용량·시간 증가, 프레임 이미지가 커져 Gemini 전송 토큰 증가. tech 트랙에서는 감수한다.
- **ffmpeg** - mp4에서 오디오(16k mono) 추출 + 분석용 프레임 추출
- **faster-whisper (large-v3)** - GPU 받아쓰기. VAD 필터 ON (무음 구간 환각 차단)
  - 유도 프롬프트: 영문 기술용어를 **영문 그대로** 받아쓰게 지시. 한글 음차 금지. (섹션 6 참고)
- **변화 감지 키프레임** - 직전 대비 화면이 바뀐 순간만 보존 (지각해시 dedup)
- **PaddleOCR (ko+en, CPU)** - 보존 프레임의 텍스트 추출. 화면의 **영문 용어·명령어·파일명**을 앵커(정답지)로 수집

### 클라우드 LLM

- `GEMINI_API_KEY` (`.env`). Tier 1 = Batch 불가 → 동기 호출 + asyncio 동시성 + 지수 백오프
- 시스템 프롬프트(규칙 + exemplary)는 호출마다 고정 → 암묵 캐싱으로 입력비 절감
- 누적 토큰·원화 실시간 추적 (로그·manifest 기록용)

## 8. 프레임 시청 처리 원칙 (**매우 중요**)

**tech 영상에서는 화면이 곧 정보다.** 발표자가 "이렇게 설정하면 됩니다"라고 말할 때 실제 설정값은 화면에만 있다. 음성만으로는 복원이 불가능하다. korean 트랙보다 이 원칙의 비중이 더 크다. 1080p 다운로드도 이 때문이다.

### 캡처 (로컬, 무손실)

- ffmpeg로 내부 초당 2~4장 분석 → 직전 프레임 대비 화면이 의미있게 바뀐 순간만 보존
  ("바뀜" = OCR 텍스트 변화 OR 시각적 변화)
- 같은 화면 연속은 지각해시로 1장 합침. 스크롤·타이핑처럼 단계별로 정보가 늘어나는 화면은 단계마다 보존
- 무음 구간이든 발화 구간이든 동일 적용

### 전송·기록

- 보존된 distinct 프레임을 전부 Gemini에 이미지로 전송
- 터미널 출력, 코드 에디터, 설정 파일, 폴더 트리 화면은 **반드시 이미지로 전송**한다. OCR 텍스트만으로는 들여쓰기와 줄바꿈이 깨져 코드가 못 쓰게 된다
- 프레임을 timestamp 목록으로 .md에 따로 나열하지 않는다. 화면에서 읽은 코드·설정은 `적용 지식` 섹션의 **코드블록에 원문 그대로 통합**한다

### 검증

생성 후 보존 프레임의 핵심 OCR 문자열(특히 **영문** 명령어·파일명·설정 키)이 출력 .md에 반영됐는지 자동 점검한다. 누락 시 1회 재생성.

```
[OCR ANCHORS]  ← 화면에서 추출한 영문 용어·명령어·파일명 목록
                 (Whisper 한글 음차 교정용 정답지)

[INSTRUCTION]
Generate the .md file per the system prompt. Output the .md content only, no preamble.
```

## 12. 작업 진입 순서

### 1단계: xlsx 상태값 초기화

`tech_yt_md_convert.xlsx`의 `변환완료여부` 컬럼에서 처리할 행을 `X`로 채운다. (현재 전부 공란)

### 2단계: `tech_yt_md_pipeline.py` 신규 작성

본 가이드를 사양서로 삼아 새로 쓴다. **`kor_yt_md_pipeline.py`를 복사해서 고치지 않는다** (이유는 섹션 2).

tech 전용으로 반드시 구현할 항목:

1. **입력**: `_vault_setup\01_md_convert\tech_yt_md_convert.xlsx` 파싱, 상태 컬럼명 `변환완료여부`, X인 행만 처리
2. **다운로드**: yt-dlp **1080p** mp4 단일 다운로드
3. **Whisper 유도 프롬프트**: 영문 기술용어를 영문 그대로 받아쓰게 지시 (섹션 6)
4. **OCR 앵커**: 화면의 **영문** 용어·명령어·파일명 수집 (한글 토큰 수집 로직 아님)
5. **Gemini 시스템 프롬프트**: 본 가이드 섹션 5·6·8 + tech exemplary
6. **출력**: 검증 통과 시 `_vault_setup\01_md_convert\result_check\convert_O\` 고정, 파일명 `tech_채널_영상제목_변환일.md`, 금지문자 치환 함수
7. **검증**: 섹션 11 체크리스트 기준. 특히 `## Transcript` 부재 확인, 한글 음차 잔존 검사, 영문 OCR 앵커 커버리지
8. **실패 처리**: `_vault_setup\01_md_convert\result_check\convert_F\` 보관, xlsx X→F
9. **로그·manifest**: `_scripts\claude_gen\`

`--track` 같은 트랙 분기 플래그는 넣지 않는다. 이 스크립트는 tech 전용이다.

### 3단계: 시범 변환

`--limit 1`로 영상 1개 변환 → Ji 검수 → 프롬프트 튜닝

### 4단계: exemplary 확정

검수 통과한 .md 1개를 tech exemplary로 고정하고 아래 섹션 13에 경로를 기록한다.

### 5단계: 나머지 실행

manifest로 재개 지원.

```
python tech_yt_md_pipeline.py --dry-run    # 작업 목록만 (API 호출 없음)
python tech_yt_md_pipeline.py --limit 1    # 시범 1개
python tech_yt_md_pipeline.py              # 전체(X 상태) 일괄
```
